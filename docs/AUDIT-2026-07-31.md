# Audit — 31 July 2026

Reviewed along four axes: **visual**, **comprehensibility**, **optimistic UI / feedback**,
and **animation**. Every item below was verified against the code or the running app —
file and line are given so each can be checked rather than taken on trust. Nothing here is
a guess; where something could not be verified it says so.

Ordered by consequence, not by effort.

---

## P0 — Money, data loss, dead ends

### 1. The landing page's "Go Pro" button has no state and swallows its errors
`src/pages/LandingPage.tsx:47-55`, button at `:198`

```ts
try { await startCheckout(plan) } catch (e) { console.error('checkout failed', e) }
```

No `disabled`, no busy state, no user-visible error. Three consequences: while the Edge
Function is called the button looks untouched, so nothing appears to happen; a second click
starts a **second checkout session**; and if it fails the visitor is told nothing, ever.

This is the primary conversion path from the public page. `UpgradePanel.tsx:37-45` already
does this correctly — busy state plus a surfaced error — so the fix is to match it.

**Fix:** busy state, `disabled` while pending, error rendered in the UI.

### 2. Billing actions fail silently on the account page
`src/pages/AccountPage.tsx:49,53`

`openBillingPortal()` and `startCheckout('yearly')` reset `busy` on failure and log to the
console. The button spins, stops, and the page looks exactly as before. Someone trying to
cancel a subscription gets no signal that it did not work — which turns a billing problem
into a support ticket or a chargeback.

**Fix:** surface the failure with a retry.

### 3. Sign-out depends on the network before it protects the device
`src/components/navigation/NavBar.tsx:152` → `src/services/supabase/cloud-sync.ts:60-63`

```ts
export async function signOutAndClearLocal(): Promise<void> {
  await useAuthStore.getState().signOut()   // network
  clearLocalAppData()                        // only if the above resolved
}
```

If the server call hangs or throws, the local data is **never cleared** and the navigation
never happens. The button also has no pending state and no re-entry guard, so it reads as
broken and can be fired repeatedly.

Note this is *not* a case for optimistic UI in the usual sense — sign-out must not merely
*appear* to succeed. But the order is wrong: clearing local state is what actually protects
this device and it must not be conditional on a network call. Revoke server-side as a
best-effort follow-up.

**Fix:** clear local first, navigate, revoke in the background; add a pending state and
guard against double-fire.

### 4. A finished session can be lost silently, taking XP and achievements with it
`src/components/casino-session/CasinoSession.tsx:89`, `src/store/stats-store.ts:128`

`recordSession(...)` is `async` and is called with no `await` and no `.catch()`. Inside it,
`await storage.saveSessionResult(result)` runs *before* XP, challenges and achievements are
awarded. The cloud write is already correctly non-blocking, but a **local** failure —
storage quota, private browsing, a serialisation error — rejects the whole chain.

Result: an unhandled promise rejection, no session recorded, no XP, no achievement check,
and nothing on screen. The player finished a session and the app forgot it.

**Fix:** catch at the call site; award XP and achievements even if persistence fails; tell
the player if their session could not be saved.

## P1 — The product misleads or hides itself

### 5. The Speed Drill's card enters from `opacity: 0`
`src/components/training/SpeedDrill.tsx:343-351`

The card being counted *is* the drill. It animates in from transparent, so any condition
that freezes animations — a backgrounded tab restored, a stalled frame loop, a device under
load — leaves the card invisible **while the timer keeps running**. The player loses the
round without ever seeing what they were meant to count.

This is the same class of defect already fixed on the loading screen: entrances move on
`transform`, never on opacity, precisely because a frozen animation must degrade to
"unanimated", never to "blank".

**Fix:** enter on transform; content legible at animation time zero.

### 6. The Speed Drill's timer bar runs on a different clock than the drill
`src/components/training/SpeedDrill.tsx:178-189` versus `:372-373`

Cards advance on `setInterval(..., speedMs)`. The bar is a Framer Motion animation of
`width` with `duration: speedMs / 1000`. Two independent clocks, throttled differently:
`setInterval` is clamped to ≥1s in background tabs, animations freeze outright. They drift,
and a progress bar that disagrees with the thing it measures is worse than no bar.

**Fix:** derive the bar from the same clock that advances the cards.

### 7. Outcome messages enter from `opacity: 0`
`src/components/table/MessageDisplay.tsx:24-27`

"Bust", "Blackjack" and the rest. Same failure mode as item 5 — under a frozen animation the
player is never told what happened at the table.

### 8. No top-level error boundary
`src/App.tsx:112-126`

`ErrorBoundary` wraps only the trainer's modes (`TrainerApp.tsx:71`). The landing page,
`/login`, `/account` and the legal pages have none: a render error there is a blank white
screen with no way back. The `<Suspense>` at `:112` also has no error boundary above it, so
a failed chunk load — routine after a deploy changes the hashes while someone has the old
page open — produces the same blank screen.

**Fix:** an error boundary above the routes, with a reload affordance.

### 9. The nav bar overflows and truncates "Analytics"
`src/components/navigation/NavBar.tsx`

Measured at a 1440px viewport: the nav needs **1154px** and its container gives **887px**.
The label renders as "Analyti". 1440 is one of the most common desktop widths, so this is
not an edge case.

**Fix:** let the group shrink, or move the secondary items behind an overflow.

## P2 — Accessibility and correctness

### 10. Reduced motion is honoured almost nowhere
Only six files respond to `prefers-reduced-motion`: `IntroSequence`, `HeroCanvas`,
`Reveal`, `use-typewriter`, `index.css`, `glow-effects.css`.

Not honoured: the entire casino session (`CardComponents`, `SeatView`, `CasinoSessionGame`),
`Hand`, `MessageDisplay`, `SpeedDrill`. These are the screens someone sits in front of for
an hour. For a user with a vestibular disorder the core product is the part that ignores
the setting they set.

**Fix:** a shared hook the animated components read, defaulting to "still" when the
preference is set.

### 11. Four animations move layout properties instead of transforms
`ShoeProgress.tsx:72` (`width`), `ShoeProgress.tsx:205` (`height`),
`ShoeVisual.tsx:125` (`width`), `SpeedDrill.tsx:372` (`width`)

Animating `width`/`height` forces layout every frame instead of running on the compositor.
The drill's bar is the one that matters — it animates continuously while cards flip.

### 12. Three open lint warnings that may be real bugs
`useGameLoop.ts:1005` and `:1469` — `useCallback` missing the `schedule` dependency.
`Hand.tsx:131` — `useEffect` calling `setShowBustText` with no dependency array.

These are in the casino game loop and the hand renderer. A missing dependency there means a
stale closure scheduling the wrong next step. **Not touched deliberately** — changing
dependencies in a timing-driven state machine is exactly how silent bugs get introduced, and
this needs a careful read rather than a lint autofix.

## P3 — Known and carried

### 13. The entitlement migration is committed but not deployed
`supabase/migrations/20260724120000_close_entitlement_hole.sql` — in git, not in the
database. **Darius executes** (`npx supabase db push`). Until then the hole is shut in code
and open where it counts.

### 14. Inter is loaded from Google Fonts at runtime
`src/index.css:1`. A render-blocking third-party request on the critical path — in front of
the loading screen — and every visitor's IP goes to Google. Real GDPR/DSG exposure for a
CH/EU audience on a site that ships a privacy page. The fix pattern already exists for
Instrument Sans (self-hosted, subsetted, OFL in `public/fonts`). Inter is OFL too.

### 15. Stripe is on sandbox keys
Live keys belong at deployment on the real domain, never on localhost, never in the repo.

### 16. The payment-path audit findings are not written down
They exist only in a chat transcript. They need to reach Christian (supervisor/CISO) before
go-live. **Cannot be reconstructed from here** — inventing security findings would be worse
than having none.

### 17. The hero renders almost black
Measured earlier: under 1% bright pixels. Deferred pending design references.

### 18. The table card shows one faded suit instead of a pip layout
`src/components/cards/PlayingCard.tsx:103-105` — a single glyph at `opacity-20`, so a four
and a seven present the same face. Recorded as a known defect; **Darius decided to keep the
current cards**, so this is documentation, not a proposal.
